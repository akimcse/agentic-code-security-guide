Foundry 설정

Agentic 코드 보안 설정의 일부로 사용할 MDASH 전용 Microsoft Foundry 리소스를 생성하고, 필수 모델 배포·TPM·콘텐츠 필터·네트워크 접근을 구성합니다.

사전 요구사항

  • 활성 구독이 있는 Azure 계정.
  • Foundry 리소스를 생성할 수 있는 역할 — 구독 또는 리소스 그룹의 Owner 등.

1. Foundry 리소스 생성

  1. Microsoft Foundry에 로그인합니다.
  2. 탐색 바에서 New Foundry 토글이 켜져 있는지 확인합니다.
  3. 드롭다운에서 Create a new project를 선택합니다.
  4. Project name을 입력합니다 (예: my-foundry-project).
  5. Advanced options에서 리소스 그룹과 위치(region)를 구성합니다.
  6. Create project를 선택합니다. 프로젝트 개요 페이지가 나타나면 준비 완료입니다.

2. 필수 값 복사

Foundry 프로젝트 홈(home) 페이지에서 서비스 연결에 필요한 값을 복사합니다. 이 두 값은 나중에 Defender 포털 온보딩(엔드포인트 입력 단계)에서 사용합니다.

  1. Project Endpoint를 찾아 복사합니다.
  2. API Key를 찾아 복사합니다.

3. 필수 모델 배포 — 2개 프로파일

Build > Models(또는 Deployments) > Deployments 탭 > Deploy a base model에서 다음을 배포합니다. 각 모델은 한 번씩만 배포합니다.

프로파일모델비고
GPT-Generalgpt-5.4 · gpt-5.3-codex · gpt-5.4-mini기본 필수 3종
MAI-Augmented Preview위 3종 + MAI-Cyber-1-Flash사이버 특화 모델(MAI-Cyber-1-Flash)로 기본 3종을 보강하는 프로파일.
참고 통합이 동작하려면 gpt-5.4, gpt-5.3-codex, gpt-5.4-mini 3종을 반드시 모두 배포해야 합니다. 커스텀 설정으로 배포하는 경우 DataZoneBatch, GlobalBatch, DeveloperTier는 선택하지 마십시오.

4. TPM 속도 제한 구성

Models > Deployment에서 각 모델 선택 → Edit → Tokens per Minute Rate Limit을 1,000,000 이상으로 → Save. 3개 모델 모두 반복.

참고 MDASH 스캔 처리량을 지원하려면 배포당 최소 1,000,000 TPM이 필요합니다.

5. 콘텐츠 필터링 구성

MDASH는 기본 필터가 유해하다고 오분류해 차단할 수 있는 보안 콘텐츠를 전송하므로, 배포 모델이 제한 없이 동작하도록 콘텐츠 필터를 관대하게 구성해야 합니다. (사전 요건: Foundry 리소스 생성 + 3개 모델 배포 완료. 프리뷰의 MAI-Cyber-1-Flash에도 동일 설정 적용.)

  1. New Foundry 토글 끄기.
  2. Guardrails + Controls > Content Filters → Create a content filter.
  3. Input Filter: 모든 심각도 임계값(Violence·Hate·Sexual·Self-harm)을 최저로, Prompt Shields for Jailbreak·Indirect Attack 끄기.
  4. Output Filter: 동일하게 최소 설정, Protected Material for text/code 등 선택적 보호 끄기.
  5. Deployment 단계에서 3개 모델 배포에 모두 연결 → 요약 검토 후 Create.
주의 이 콘텐츠 필터링은 MDASH 스캔 전용으로 의도적으로 관대합니다. 반드시 MDASH 전용 Foundry 엔드포인트를 만들어 사용하고, 다른 워크로드에는 쓰지 마세요.

6. MDASH 접근 허용 (네트워킹 제한 시)

MDASH는 자격 검증·스캔 실행을 위해 Foundry 엔드포인트에 접근합니다.

Foundry 공용 접근 설정조치
All networks❌ 불필요 — 그대로 동작
Selected networks and private endpoints✅ MDASH 공인 IP를 허용해야 온보딩 검증 통과 (미등록 시 Validate 실패)
  • 옵션 1 (권장) — 제공된 foundry-ip-rules.sh 스크립트로 필요한 IP(ASPM Web API + ScannerService 대역)를 한 번에 추가. Azure CLI·jq 설치, Azure 로그인, 올바른 구독 선택, Foundry 리소스에 대한 Contributor/Owner 권한 필요.
  • 옵션 2 — Azure 포털 Foundry 리소스 → Resource Management > Networking > Firewall의 Address range에 IP 수동 추가 후 Save. (공식 문서에는 옵션 1의 스크립트 방식만 안내되어 있으며, 옵션 2는 동등한 포털 대안입니다.)
중요 이 IP 허용은 Azure의 Foundry 리소스 방화벽 설정이며, 고객 사내망(업무망 등) 방화벽과는 무관합니다. MDASH는 Foundry 엔드포인트에 공인 IP로 접근하므로(퍼블릭 경로), Foundry 네트워킹이 Selected networks and private endpoints인 경우 위 MDASH 공인 IP 대역을 반드시 허용해야 검증·스캔이 동작합니다.

Foundry 연결 해제

다른 Foundry로 교체·제거하려면 Initiative > Settings에서 Disconnect. 연결만 제거될 뿐 Foundry 리소스 자체는 삭제되지 않으며, 대안 없이 해제하면 에이전트 코드 스캐닝이 비활성화됩니다.
