Azure DevOps 커넥터 생성

소스 코드 관리(SCM)로 Azure DevOps(ADO)를 쓰는 조직의 권장 온보딩 경로입니다. ADO 조직을 연결해 저장소를 온보딩하면, 로컬 설치 없이 포털에서 원격 On-demand 스캔을 트리거할 수 있습니다. 흐름은 GitHub 커넥터와 거의 동일하며, 사전 권한·인증 방식만 ADO에 맞게 다릅니다.

사전 요구사항

커넥터를 승인·재승인하려면 아래 권한이 모두 필요합니다.

  • Defender 포털 접근 — 최소 Security Administrator (Entra ID).
  • 연결할 각 ADO 조직에서 Project Collection Administrator 역할 (Organization Settings > Security > Permissions).
  • 각 ADO 조직에서 Basic 또는 Basic + Test Plans 액세스 레벨 (Organization Settings > Users). Stakeholder 레벨은 불가.
Microsoft Defender Code 앱 프로비저닝 테넌트에 Microsoft Defender Code 앱이 프로비저닝돼 있어야 합니다. 다음 두 조건을 모두 충족하면 프로비저닝 스크립트를 생략할 수 있습니다. ① 조직이 Microsoft 365 E5 라이선스 보유(MDASH 온보딩 중 앱 자동 프로비저닝), ② ADO 조직 테넌트가 Defender 테넌트와 동일. 그 외의 경우 커넥터 생성 전에 프로비저닝 스크립트를 먼저 실행하세요.
주의 동일 ADO 조직이 이미 Azure 포털의 Azure DevOps 커넥터로 연결돼 있다면, Defender 포털로 연결하기 전에 Azure 포털 커넥터를 먼저 해제해야 합니다. 해제 시 그 커넥터에 연결된 Defender for DevOps Security 기능은 더 이상 사용할 수 없습니다.

1단계: 테넌트 준비

커넥터 생성 흐름에 접근하려면 테넌트에 Cloud Security가 준비돼 있어야 합니다. 이미 활성화됐다면 Prepare my tenant 옵션이 보이지 않고 바로 진행됩니다.

  1. Cloud security > Overview 이동.
  2. Prepare my tenant 선택.
  3. 테넌트 준비 확인.

2단계: 커넥터 마법사 열기

  1. Defender 포털에서 MDASH Initiative > Settings로 이동. (이니셔티브 접근은 온보딩의 진입점 참조.)
  2. Create and Manage connectors 선택 → Cloud Security Connectors 페이지로 이동됨.
  3. Connectors 탭에서 목록의 Azure DevOps 커넥터 선택.
  4. (선택) 커넥터 이름 입력. 비우면 기본 이름 자동 부여. → Next.

3단계: 접근·권한 구성

권한 계층설명
Read (기본·제거 불가)변경 없이 저장소를 스캔하고 보안 이슈를 식별. 소스코드·저장소 메타데이터, 파이프라인·서비스 연결, 연결된 조직·프로젝트의 보안 시그널 읽기.
Write (선택)AI 생성 수정본을 담은 PR 생성, 교정(remediation) 과정에서 저장소 콘텐츠·메타데이터 업데이트 등. 스캐닝·탐색만 하려면 Read로 충분.

권한 선택을 검토하고 Next.

4단계: 승인 및 구성 (Authorize)

DevOps security 앱에 ADO 리소스 접근 권한을 부여하고, 온보딩할 조직을 선택합니다.

  1. Authorize Entra ID 선택.
  2. 로그인 대화 상자에서 대상 ADO 조직의 Project Collection Administrator 계정을 선택.
  3. 승인 성공 시, 해당 계정에서 발견된 모든 ADO 조직이 프로젝트 수와 함께 나열됨.
  4. 온보딩할 조직을 선택하고 Next.
참고 발견된 조직 중 일부만 선택할 수 있습니다. 선택하지 않은 조직은 무시되며, 나중에 커넥터를 편집해 추가할 수 있습니다.

5단계: 검토 및 활성화

Review and finish 페이지에서 커넥터 이름, 온보딩될 ADO 조직 목록(프로젝트 수 포함), 접근·권한 범위(Read 및 선택 시 Write)를 확인하고 Activate.

참고 활성화 후 온보딩된 저장소에 대해 On-demand 스캔을 트리거할 수 있게 되기까지 최대 1시간이 걸릴 수 있습니다.
