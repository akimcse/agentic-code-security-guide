스캔 결과 검토

터미널에서 생성되는 HTML/SARIF 결과 파일을 검토하고, Defender 포털의 MDASH 이니셔티브 대시보드에서 조직 전체 발견 항목을 분류·추적하는 방법을 다룹니다.

1. 터미널 결과 검토

스캔이 완료되면 Defender CLI가 스캔을 시작한 디렉터리에 결과 파일을 자동 생성합니다. 두 가지 형식이 제공됩니다.

파일 형식적합한 용도
HTML 리포트사람이 검토 — 발견 항목·심각도·영향받는 코드 경로·권장 수정에 대한 시각적 요약.
SARIF 파일프로그래밍적 처리 — CI/CD 통합, 보안 대시보드 임포트, 커스텀 리포팅 워크플로.

사전 요구: Defender CLI 설치·인증 + Scan results (Read) 권한 + 완료된 AI 스캔(defender scan ai-scan wait <JOB_ID>).

HTML 리포트

스캔을 시작한 디렉터리로 이동해 생성된 .html 파일을 브라우저에서 엽니다. 리포트에는 다음이 포함됩니다.

  • 발견 항목 요약 — 심각도별(Critical·Important·Moderate·Low) 취약점 총계.
  • 심각도 분석 — 각 항목의 CWE 분류·심각도 등급·검증 단계 신뢰도 점수.
  • 영향받는 코드 경로 — 파일 경로·라인 번호·취약점 위치 코드 스니펫.
  • 권장 수정 — 각 항목에 대한 AI 생성 수정 제안.

SARIF 파일 (v2.1.0)

OASIS SARIF v2.1.0 사양을 따르는 기계 판독 결과로, 업계 표준 보안 도구와 호환됩니다. 용도: CI/CD 파이프라인 임포트(GitHub Advanced Security·Azure DevOps의 PR 주석), SIEM·보안 자세 관리 도구 대시보드 공급, 커스텀 리포트 작성, 스캔 간 비교를 통한 수정 속도 추적.

섹션설명
runs[].results[]규칙 ID·심각도·메시지·위치를 포함한 개별 발견 항목 배열.
runs[].tool스캐닝 하네스 버전·구성 메타데이터.
runs[].results[].locations[]각 발견 항목의 물리적·논리적 위치(파일 경로·라인·컬럼).
runs[].results[].codeFlows[]취약점 도달 경로를 보여주는 단계별 실행 경로(prove 단계에서 가능할 때).
# 완료된 스캔 결과 다운로드
defender status wait <JOB_ID> -o results.sarif

2. Defender 포털 — MDASH 이니셔티브

Agentic 코드 스캔 발견 항목은 Microsoft Security Exposure Management(MSEM)를 통해 포털에 표시됩니다. Codename MDASH - Agentic code scanner 이니셔티브는 스캔된 모든 저장소의 발견 항목을 집계해 중앙 집중식 취약점 추적·수정 뷰를 제공합니다. 이 페이지는 AI 스캐너 발견 항목 전용이며 비-AI 스캐너 결과는 표시하지 않습니다.

참고 스캔은 두 경로(Defender CLI, 커넥터를 통한 포털 기반 원격 스캔)로 이 페이지에 도달합니다. 원격 결과는 CLI 결과와 구분되도록 페이지 전반에 라벨링됩니다. 페이지는 최근 90일 활동만 반영합니다.

분류(Triage) — AI가 발견 항목을 그룹화하는 방식

모든 발견 항목은 심각도(Critical·High·Medium·Low)와 신뢰도(Likely·Suspect·Unlikely)의 조합으로 3개 버킷에 분류됩니다.

버킷의미해야 할 일
Validated by AI scannerAI가 실제 취약점이라고 확신하며, 심각도도 충분히 높음.지금 조치 — 수정하거나 개발자에게 배정.
Flagged for review고심각도지만 AI가 스스로 완전히 검증하지 못함.일시 정지 — 사람이 조사 후 조치.
Low priority신뢰도와 무관하게 저·중 심각도 항목.연기·음소거 가능 — 배경 노이즈.

스캔 출처 구분: CLI vs 원격

모든 스캔·발견 항목은 다음 신호를 담습니다: Source(원격 스캔+SCM 아이콘 / CLI), Status(Succeeded·Running·Canceled·Failed), Tokens consumed(진행 중이면 "—").

페이지 구성 — 3개 탭

탭내용브랜치 범위
Overview점수, 14일 추세, 분류 퍼널, 최신 스캔, 가장 흔한 CWE, 권장 항목이 가장 많은 저장소기본 브랜치 중심(일부 패널은 전체 브랜치)
Security recommendations(저장소, 브랜치) 조합별 최신 스캔에서 발견 항목당 1행전체 브랜치(기본으로 필터 가능)
Scans최근 90일 내 실행된 모든 스캔 + 개별 드릴다운전체 브랜치
참고 Overview의 점수·분류 퍼널은 "지금 배포된 코드는 어떤 상태인가?"에 답합니다. 관례상 배포 코드는 각 저장소의 기본 브랜치에 있으므로 기본 브랜치로 범위가 지정됩니다. Recommendations 탭은 더 넓어 모든 브랜치를 자유롭게 넘나들 수 있습니다.

Overview 탭 — 6개 패널

  • Score — 0~100%의 도넛 차트(높을수록 좋음). 탐지된 취약점 기반의 심각도 가중 코드 건강도. 기본 브랜치만. Understand score calculation으로 계산 상세 확인.
  • 14-day score trend — 점수 변화를 보여주는 14일 선형 차트로 수정 작업 효과 확인. 기본 브랜치만.
  • Latest AI code scans — 모든 저장소·브랜치의 최근 3개 스캔 피드(활동 피드라 전체 브랜치). 저장소·브랜치, 권장 항목 수, 3개 버킷 색상 막대(Validated는 CSV Export 가능), View scan, Source/SCM, Run type, Status 표시.
  • Repositories with the most recommendations — 권장 항목 볼륨 순 저장소 표. 기본 브랜치·전체 브랜치 수를 나란히 비교.
  • Recommendation triage funnel — 심각도 → 버킷 흐름을 명시적으로 시각화하는 유일한 패널. 단계 선택 시 해당 단계로 사전 필터된 Recommendations 탭이 열림(기본 브랜치 범위). 기본 브랜치만.
  • Weaknesses with the most recommendations — 가장 흔한 약점 유형(CWE) 표(예: CWE-89). Weakness ID·Name·기본/전체 브랜치 수·영향 저장소·View recommendations.
Total findings (default branches)
   ├── Critical + High severity
   │       ├── Validated by AI scanner  → Export
   │       └── Flagged for review
   └── Low + Medium severity → Low priority
참고 MDASH 발견 항목은 현재 Secure Score나 Risk Score에 영향을 주지 않습니다. 유일하게 영향받는 것은 MDASH 이니셔티브 내의 Codename MDASH 위험 점수입니다.

Security recommendations 탭

개별 권장 항목을 검토·조치하는 주요 작업 공간으로, (저장소, 브랜치)별 최신 스캔에서 도출됩니다. 기본은 기본 브랜치 범위이며 전체 브랜치로 전환 가능합니다. 상단에 4개 KPI(Total · Validated by AI scanner · Flagged for review · Low priority)가 표시됩니다.

테이블 컬럼: Severity · Confidence(Likely·Suspect·Unlikely) · Recommendation · Weakness ID(CWE) · Repository · Branch · Trigger(Source+Run type) · File · Scan start time.

기본 정렬: 버킷(Validated → Flagged → Low) → 버킷 내 심각도(Critical → High → Medium → Low) → 심각도 내 신뢰도(Likely → Suspect → Unlikely).

  • 최신 스캔만 — 각 행은 해당 (저장소, 브랜치)의 가장 최근 스캔을 반영. 새 스캔이 실행되면 목록이 자동 갱신.
  • 스캔 간 지속 — 최신 스캔이 더 이상 탐지하지 않을 때까지 항목이 목록에 유지.
  • CLI·원격 통합 — "최신 스캔 우선" 원칙이 두 출처 모두에 적용.

Scans 탭

최근 90일 내 성공한 모든 스캔(모든 저장소·브랜치). 상단 KPI: 스캔 수 · 스캔된 저장소 수 · Succeeded · Running · Failed.

컬럼: Status · Repository · Branch · Trigger · Tokens · Started · Duration · Severity(스택 막대) · Triage(스택 막대) · Run ID(예: run_d73220eb).

행을 선택하면 스캔 상세 드로어가 열립니다.

  • Overview 서브탭 — Summary(Started·Finished·Duration·Tool name·Trigger·SCM·Total tokens), Scan identity(Repository·Branch·Run ID), High-volume recommendations(가장 노출된 파일·가장 흔한 CWE), Triage, 심각도별 권장 항목 막대.
  • Recommendations 서브탭 — 해당 스캔 브랜치로 범위가 지정된 발견 항목. Severity·Validation(버킷)·Recommendation·Weakness ID·File 컬럼과 동일한 필터·검색·Export 경험.
참고 메인 Recommendations 탭은 항상 브랜치별 최신 스캔을 보여줍니다. 드로어는 특정 과거 스캔이 실행 시점에 발견한 내용을 정확히 볼 수 있는 유일한 곳으로, 감사·사고 검토·연속 실행 비교에 유용합니다.

데이터 범위 및 신선도

  • 90일 가시성 창 — 최근 90일 내 완료된 스캔만 표시. 오래된 스캔은 자동 소멸.
  • 성공한 스캔만 — Running·Failed·부분·취소 스캔은 표시되지 않음.
  • 만료된 링크 — 90일 초과 스캔 직접 링크는 "Scan not found" 반환.
