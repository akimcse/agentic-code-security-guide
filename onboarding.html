온보딩 시작하기 (Getting Started with Codename MDASH)

조직을 Agentic 코드 보안에 연결하고 스캔을 시작하기 위한 사전 요구사항, 권한(RBAC), 온보딩 5단계를 다룹니다.

사전 요구사항 체크리스트

  • Microsoft Entra ID에서 전역 관리자 또는 보안 관리자 역할.
  • 온보딩 중 조직을 대표하여 MDASH 이용 약관을 수락할 권한.
  • MDASH 전용 Microsoft Foundry 리소스를 생성할 Azure 구독·리소스 그룹.
  • 필수 모델을 배포할 권한 (모델 목록은 Microsoft Foundry 연결 > 필수 모델 배포 참조).
  • Foundry 네트워킹이 Selected networks and private endpoints인 경우, MDASH 접근 허용 조치 필요.
  • 다음 AI 스캔 경로 중 최소 하나 (나머지는 나중에 추가 가능): 원격 스캔(GitHub 커넥터, 권장) 또는 Defender CLI.
  • 아웃바운드 제한 시 허용 목록 도메인 허용.
  • Defender 포털에서 Exposure Management·Initiatives를 열 권한, 그리고 Foundry 프로젝트 엔드포인트·API 키.

Defender RBAC 권한 (최소 권한 부여)

권한용도
Run scan (Manage)On-demand 또는 CLI 스캔 트리거
Upload results (Manage)CLI 스캔 결과를 Defender에 업로드
Scan results (Read)포털·이니셔티브에서 발견 항목 조회
Scan results (Manage)발견 항목 분류·해제·관리

커스텀 역할 생성 절차

  1. Microsoft Defender 포털 로그인.
  2. 탐색 창에서 System > Permissions.
  3. Microsoft Defender XDR 아래 Roles > Create custom role.
  4. Basics에서 역할 이름·설명 입력.
  5. Choose permissions에서 Agentic code security > AI Scan Security를 확장해 필요한 권한 설정.
  6. Apply → Next로 사용자·데이터 원본 할당 후 Submit.

진입점(Entry points)

  • Exposure Management > Overview → Agentic code security 선택
  • Exposure Management > Initiatives → Codename MDASH - Agentic code scanner 이니셔티브 선택

온보딩 단계

  1. 약관 수락 — 약관 검토 후 체크박스로 수락(수락해야 Save 가능).
  2. Microsoft Foundry 리소스 연결 — Foundry 연결 절차 수행.
  3. Defender 포털 온보딩 — Project endpoint·API key 입력 → Validate → Save (검증 성공해야 저장 가능).
  4. AI 스캔 설정 — GitHub 커넥터(원격, 권장) 또는 Defender CLI 구성. 이 단계는 나중에 완료해도 되지만, 완료 전에는 스캔이 정상 실행되지 않습니다.
  5. 권장 사항 검토 — 스캔 실행 후 포털에서 발견 항목 확인.
