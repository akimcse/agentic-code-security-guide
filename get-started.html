시작하기

조직을 Agentic 코드 보안(Codename MDASH)에 연결하고 스캔을 실행하기 위한 온보딩, Microsoft Foundry 연결, GitHub 커넥터, Defender CLI 인증 설정을 다룹니다.

1. 온보딩 개요 및 사전 요구사항

온보딩을 완료하려면 다음이 필요합니다.

  • Microsoft Entra ID에서 전역 관리자(Global Administrator) 또는 보안 관리자(Security Administrator) 역할.
  • 온보딩 중 조직을 대표하여 MDASH 이용 약관을 수락할 권한.
  • MDASH 전용 Microsoft Foundry 리소스를 생성할 Azure 구독 및 리소스 그룹.
  • Global Standard 배포 유형으로 다음 3개 모델을 모두 배포할 권한: gpt-5.4, gpt-5.3-codex, gpt-5.4-mini.
  • MDASH 전용으로만 사용하는 Foundry 엔드포인트.
  • 아래 두 스캔 경로 중 최소 하나 (나머지는 나중에 추가 가능).
🌐

옵션 1 — 원격 스캔 (권장)

GitHub 커넥터로 연결. 로컬 설치 없이 포털에서 On-demand 스캔. 커넥터 관리 권한 + GitHub 조직 Owner + 테넌트 Cloud Security 준비 필요.

💻

옵션 2 — Defender CLI

Azure CLI 설치, Microsoft Defender Code 엔터프라이즈 앱(E5는 자동), 플랫폼별 CLI 바이너리. 로컬 대화형 스캔은 Run scan (Manage) 권한 필요.

참고 아웃바운드 트래픽이 제한된 환경이라면 개요 페이지의 허용 목록에 있는 도메인을 허용해야 합니다.

Defender RBAC 권한 (사용자별 최소 권한 부여)

권한용도
Run scan (Manage)On-demand 또는 CLI 스캔 트리거
Upload results (Manage)CLI 스캔 결과를 Defender에 업로드
Scan results (Read)포털/이니셔티브에서 발견 항목 조회
Scan results (Manage)발견 항목 분류·해제·관리

커스텀 역할 생성 절차 (Defender 통합 RBAC)

  1. Microsoft Defender 포털에 로그인합니다.
  2. 탐색 창에서 System > Permissions를 선택합니다.
  3. Microsoft Defender XDR 아래에서 Roles > Create custom role을 선택합니다.
  4. Basics 탭에서 역할 이름과 설명을 입력합니다.
  5. Choose permissions에서 Agentic code security를 확장하고, AI Scan Security 아래에서 필요한 권한 수준을 설정합니다.
  6. 권한을 검토하고 Apply → Next로 사용자·데이터 원본을 할당한 뒤 Submit합니다.

온보딩 진입점 및 단계

Defender 포털의 다음 위치 중 하나에서 온보딩을 시작합니다.

  • Exposure Management > Overview → Agentic code security 선택
  • Exposure Management > Initiatives → Codename MDASH - Agentic code scanner 이니셔티브 선택
  1. 약관 수락 — 약관을 검토하고 체크박스로 수락(수락해야 Save 가능).
  2. Microsoft Foundry 리소스 연결 — 아래 2단계 참조.
  3. Defender 포털 온보딩 — Project endpoint와 API key 입력 → Validate → Save(검증 성공해야 저장 가능).
  4. AI 스캔 설정 — GitHub 커넥터(원격, 권장) 또는 Defender CLI 경로 구성.
  5. 권장 사항 검토 — 스캔 실행 후 포털에서 발견 항목 확인.

2. Microsoft Foundry 연결

Agentic 코드 보안 설정의 일부로 사용할 Microsoft Foundry 리소스를 생성합니다.

Foundry 리소스 생성

  1. Azure 포털에서 Microsoft Foundry를 검색하고, Use with Foundry 아래에서 Foundry를 선택합니다.
  2. Create를 선택해 새 Foundry 리소스를 만듭니다. 구독·리소스 그룹을 선택하고, 리소스 이름·리전·기본 프로젝트 이름을 입력합니다.
  3. Review + create → Create → 배포 완료 후 Go to resource.

필수 모델 배포

프로젝트를 열고(New Foundry 토글 활성화 확인) Build > Deployments > Deploy a base model에서 다음 3개 모델을 각각 한 번씩 배포합니다.

gpt-5.4 gpt-5.3-codex gpt-5.4-mini
참고 통합이 동작하려면 3개 모델을 모두 배포해야 합니다. 커스텀 설정을 쓴다면 배포 유형은 반드시 Global Standard여야 합니다.

TPM 속도 제한 구성

Models > Deployment에서 각 모델을 선택 → Edit → Tokens per Minute Rate Limit을 1,000,000 이상으로 설정 → Save. 3개 모델 모두 반복합니다.

참고 MDASH 스캔 처리량을 지원하려면 배포당 최소 1,000,000 TPM이 필요합니다.

필수 값 복사

서비스 연결에 필요한 Project Endpoint와 API Key를 복사해 둡니다.

콘텐츠 필터링 구성

MDASH는 기본 필터가 유해하다고 오분류해 차단할 수 있는 보안 콘텐츠를 전송하므로, 배포 모델이 제한 없이 동작하도록 콘텐츠 필터를 구성해야 합니다.

  1. New Foundry 토글을 끕니다.
  2. Guardrails + Controls > Content Filters → Create a content filter.
  3. Input Filter: 모든 심각도 임계값(Violence·Hate·Sexual·Self-harm)을 가능한 최저로, Prompt Shields for Jailbreak 및 Indirect Attack을 끕니다.
  4. Output Filter: 동일하게 모든 임계값을 최소로 설정하고, Protected Material for text/code 등 선택적 보호를 끕니다.
  5. Deployment 단계에서 필터를 3개 모델 배포에 모두 연결 → 요약 검토 후 Create.
주의 이 콘텐츠 필터링은 MDASH 스캔 전용으로 의도적으로 관대하게 설정됩니다. 반드시 MDASH 전용 Foundry 엔드포인트를 만들어 사용하고, 다른 워크로드에는 이 엔드포인트를 사용하지 마세요.

MDASH 접근 허용 (네트워킹 제한 시)

Foundry 리소스의 공용 접근이 All networks이면 조치가 필요 없습니다. Selected networks and private endpoints로 설정된 경우 인바운드가 차단되어 온보딩 시 검증이 실패하므로, 필요한 IP를 허용해야 합니다.

  • 옵션 1 (권장) — 제공된 foundry-ip-rules.sh 스크립트로 필요한 IP(ASPM Web API + ScannerService 대역)를 한 번에 추가합니다. Azure CLI·jq 설치, Azure 로그인, 올바른 구독 선택, Foundry 리소스에 대한 Contributor/Owner 권한이 필요합니다.
  • 옵션 2 — Azure 포털의 Foundry 리소스 → Resource Management > Networking > Firewall의 Address range에 IP를 수동으로 추가 후 Save.
Foundry 연결 해제 다른 Foundry로 교체하거나 제거하려면 Initiative > Settings에서 Disconnect. 연결만 제거될 뿐 Foundry 리소스 자체는 삭제되지 않으며, 대안 없이 해제하면 에이전트 코드 스캐닝이 비활성화됩니다.

3. GitHub 커넥터 생성 (원격 스캔, 권장)

GitHub 조직을 연결하고 저장소를 온보딩하면, 온보딩된 저장소에 대해 원격 On-demand 스캔을 트리거할 수 있습니다.

사전 요구: Defender 포털 커넥터 관리 권한(최소 Security Administrator) + 연결할 GitHub 조직의 Organization Owner.

주의 동일 GitHub 조직이 이미 Azure 포털의 GitHub 커넥터로 연결되어 있다면, Defender 포털로 연결하기 전에 Azure 포털 커넥터를 먼저 해제해야 합니다. 해제 시 해당 커넥터의 Defender for Cloud DevOps Security 기능은 더 이상 사용할 수 없게 됩니다.
  1. 테넌트 준비 — Cloud security > Overview > Prepare my tenant. 이미 활성화된 경우 이 옵션이 표시되지 않습니다.
  2. 커넥터 마법사 열기 — System > Settings > Defender for Cloud > Connectors에서 GitHub 커넥터 선택(또는 MDASH Initiative > Settings에서 접근).
  3. 접근·권한 구성 — Read(기본·제거 불가)는 변경 없이 스캔, Write(선택)는 GitHub 이슈·PR 생성 등 워크플로 통합에 필요.
  4. GitHub App 승인·설치 — Install → GitHub 로그인·조직 선택 → 설치 확인.
  5. 검토 및 활성화 — 커넥터 이름·권한 범위·조직·저장소 수를 확인하고 Activate.
참고 커넥터 활성화 후 온보딩된 저장소에 대해 On-demand 스캔을 트리거할 수 있게 되기까지 최대 1시간이 걸릴 수 있습니다.

4. Defender CLI 인증 설정

로컬 또는 CI/CD 파이프라인에서 스캔을 실행하기 위한 인증 방식은 두 가지입니다.

인증 방식용도필요 권한
앱 기반(App-based)CI/CD 파이프라인 등 비대화형 자동화앱 등록·권한 추가에 Application Administrator, 관리자 동의에 Global Administrator. 앱에 AIScan.enabled(스캔) / AIScan.Upload(업로드) 권한.
대화형(Interactive)로그인 사용자의 로컬 터미널 스캔Security Administrator + Defender 통합 RBAC 권한.

Microsoft Defender Code 엔터프라이즈 앱 설치 (필요 시)

두 인증 방식 모두에 필요합니다. E5 라이선스 테넌트는 온보딩 중 자동 프로비저닝되므로 스크립트 실행이 필요 없습니다. E5가 아니면 아래를 수행합니다.

winget install -e --id Microsoft.AzureCLI

# Grant-DefenderAdminConsent.ps1 저장 후 실행
./Grant-DefenderAdminConsent.ps1 -TenantId <tenant-id>

Azure 로그인 완료 후, Microsoft Entra ID > Overview에서 Microsoft Defender Code를 검색해 Enterprise applications에 나타나는지 확인합니다. (스크립트 전문은 참조 페이지 참고.)

앱 기반 인증 구성

  1. Azure 포털 > App registrations > New registration으로 앱을 등록합니다.
  2. Manage > API permissions > Add a permission > APIs my organization uses에서 Microsoft Defender Code를 검색합니다.
  3. Application permissions에서 AIScan.enabled(스캔 실행)·AIScan.Upload(결과 업로드)를 추가합니다. (AIScan.View는 현재 권한에 영향 없음.)
  4. Global Administrator가 Grant admin consent로 동의합니다.
  5. Certificates & secrets > New client secret으로 시크릿을 생성하고 값을 안전하게 저장합니다(재확인 불가). Application (client) ID와 Directory (tenant) ID를 기록합니다.

CI/CD에서는 다음 값을 암호화된 시크릿으로 저장하고 워크플로 잡에 환경 변수로 노출합니다.

DEFENDER_ASPM_TENANT_ID
DEFENDER_ASPM_CLIENT_ID
DEFENDER_ASPM_CLIENT_SECRET
주의 이 시크릿을 소스 제어에 커밋하거나 워크플로 로그에 포함하지 마세요. 시크릿은 정기적으로 교체하고 만료 전에 교체해 파이프라인 실패를 방지하세요.

대화형 인증 구성

사용자 셸에 테넌트 환경 변수를 설정한 뒤 device code 로그인 흐름으로 로그인합니다.

DEFENDER_DFD_TENANT_ID=<tenant-id>

az login \
  --tenant <DEFENDER_DFD_TENANT_ID> \
  --scope b1a78a13-a596-4366-b37d-406048fa4a23/Defender.InteractiveLogin \
  --allow-no-subscriptions \
  --use-device-code

콘솔에 표시된 device code를 복사해 브라우저 로그인 페이지에서 해당 테넌트 접근 권한이 있는 계정으로 로그인하고, 코드를 붙여넣어 인증을 완료합니다.
