아키텍처 (보안 설계)

"MDASH = 모델 + 스캐닝 하네스"가 아닙니다. 진짜 제품은 그것들을 둘러싼 Defender급 보안 시스템 — 통제·격리 경계·운영 관행·거버넌스·컴플라이언스 태세 — 입니다. 이 페이지는 공식 아키텍처 블로그의 기술 내용을 한글로 정리한 요약입니다.

핵심 한 줄 AI는 "통제된 Microsoft Security 환경 안에서 일하는 고도 권한 보안 연구자"처럼 동작합니다 — 유용할 만큼 강력하되, 데이터가 신뢰 경계를 벗어날 수 없도록 격리·모니터링·제약·거버넌스됩니다.

한눈에 — 4가지 설계 기둥

🏗️

Defender Foundations

격리된 연구 실험이 아니라 프로덕션 Microsoft Security 서비스. Defender XDR·Sentinel과 같은 보안·거버넌스·운영 기반 위에서 동작.

🌍

Regional Operation

고객이 이미 쓰는 클라우드·리전에서 Defender와 함께 동작. 데이터 레지던시·소버린 클라우드·컴플라이언스 약속을 그대로 승계.

🔒

AI & Data Containment

소스코드·발견·보안 데이터를 통제된 경계 안에 유지. 샌드박스 격리·최소 수명·최소 범위.

⚖️

Responsible Governance

보안·프라이버시·컴플라이언스·책임 있는 AI·침투 테스트·운영 준비성 리뷰를 엔지니어링 과정에 내장.

왜 이런 설계가 필요한가

같은 발전이…방어자에게공격자에게
코드 작성·시스템 분석·취약점 발견을 가속✅ 치명적 약점을 더 일찍 발견⚠️ 정교한 취약점 연구가 더 쉬워짐

AI는 방어자가 약점을 더 일찍 찾게 해주는 동시에, 공격자의 진입 장벽도 낮춥니다. 그래서 고객에게 필요한 것은 강력한 AI만이 아니라 신뢰된 보안 아키텍처 안에서 제공되는 강력한 AI입니다.

따라서 MDASH의 제품 정의는 "모델과 하네스"에 그치지 않고, 그것을 둘러싼 종합 보안 시스템(통제·격리 경계·운영 관행·거버넌스·컴플라이언스)까지 포함합니다. 고객은 통제권을 잃지 않고 프론티어 AI의 혜택을 누리며, 그 발견을 Microsoft Defender 안에서 활용합니다.

프로덕션 Microsoft Defender 서비스로 구축

MDASH는 처음부터 프로덕션 Microsoft Security 서비스로 설계됐습니다 — 독립 실험도, 분리된 연구 환경도, 단절된 보안 도구도 아닙니다. Defender XDR·Sentinel과 동일한 기반 위에서 동작하므로, 고객은 민감 데이터를 새로운 신뢰 모델로 옮길 필요가 없습니다.

🗂️

MDASH가 다루는 민감 데이터

소스코드취약점 발견악용 가능성 분석위협 인텔리전스 신원 신호런타임 노출보안 인시던트리메디에이션 워크플로

🛡️

승계하는 Defender급 운영 규율

신원·접근 제어서비스 간(S2S) 권한 부여로깅·감사 가능성 보안 리뷰 게이트컴플라이언스 정렬프라이버시 리뷰 책임 있는 AI 리뷰프로덕션 운영

목표는 고객이 MDASH를 "처음부터 평가해야 하는 별도 AI 시스템"이 아니라, 이미 신뢰하는 Microsoft 보안 플랫폼의 확장으로 경험하게 하는 것입니다.

Defender가 있는 곳에서 글로벌 운영

보안 결정은 데이터 거버넌스·규제·운영 요건과 함께 평가됩니다. 특히 분석 대상이 독점 소스코드·고위험 취약점·미공개 보안 발견일 수 있는 AI 보안 시스템에서는 "어디에 저장·처리되고 누가 접근하는지"가 핵심입니다. 그래서 MDASH는 Defender가 운영되는 클라우드·리전에서 함께 동작하고, 취약점 발견이 민감 데이터를 기존 경계 밖으로 옮기는 이유가 되지 않도록 설계됐습니다.

🌐

Defender에서 승계하는 것

리전 배포 모델데이터 레지던시 약속소버린 클라우드 투자 고객 거버넌스 역량Microsoft 컴플라이언스 약속

📦

고객 Defender 데이터로 취급

발견(findings)저장소 메타데이터스캔 아티팩트 취약점 분석보안 인텔리전스

Foundry MDASH는 AI 추론을 위해 Microsoft Foundry와 통합되며, Foundry로 처리되는 데이터는 해당 Foundry의 데이터 처리·컴플라이언스 약속을 따릅니다.

컨테인먼트 — 데이터가 경계를 벗어나지 않도록

가장 중요한 원칙은 컨테인먼트(containment)입니다. 보안 데이터를 다루는 AI는 범용 생산성 시스템과 다르게 취급돼야 합니다.

이 데이터가 새면…왜 위험한가
취약점 리포트공격자에게 공격 로드맵이 됨
소스코드지식재산·시크릿이 노출됨

샌드박스·에이전트 같은 실행 환경만 Microsoft가 운영하는 MDASH 통제 환경에 있습니다(고객 테넌트 내부가 아님). Foundry(고객 Azure 리소스)와 Defender는 모두 고객의 동일 Entra 테넌트에 속하며, 추론은 Foundry에서, 결과·인텔리전스는 Defender 테넌트에 귀속됩니다.

샌드박스는 스캔마다 분리되어 영속화·크로스테넌트 접근·워크로드 간섭을 방지하고, 민감 데이터의 수명을 최소화하며 분석에 필요한 최소 범위만 요구합니다.

인텔리전스는 조직에 귀속

🚫

흡수하지 않음

스캐닝·조사 중 생성된 컨텍스트를 수확 대상 '배기가스(exhaust)'로 취급하지 않음.

🏠

테넌트에 로컬

인텔리전스는 고객 테넌트에 로컬로 유지되고, 조직에 속한 자산으로 취급.

🛡️

경쟁 우위 보존

지식재산·운영 지식·보안 관행에 새 리스크를 더하지 않고 AI 도입 가능.

일급 통제로서의 보안 격리 (네트워크)

네트워크 동작은 AI 하네스의 가장 큰 리스크 영역입니다. 두 접근을 비교하면:

항목일반 AI 하네스 (실험용)MDASH (보안 프로덕션)
네트워크 접근외부 사이트·레지스트리·API·페이스트·검색엔진 등 광범위 접근 가정핵심 서비스는 사설 네트워킹 경계 뒤, 통제된 서비스 경로로만 통신
인그레스·이그레스느슨함 → 코드·발견·프롬프트·익스플로잇 유출 경로제한·모니터링·인가·검증, 외부 통신 통제
런타임 확장도구 다운로드·패키지 설치·프레임워크 임포트 자유새 코드·의존성에 닫힘 — 확장 불가

신뢰되지 않은 소프트웨어 도입을 막음으로써, 모델이 새 도구로 의도된 경계를 넘는 AI 이스케이프·통제 우회의 가장 흔한 패턴을 제거합니다. 이는 양쪽 모두에 중요합니다 — 고객은 데이터 유출이 없다는 확신을, Microsoft는 자사 위협 인텔리전스·탐지 컨텍스트가 새지 않는다는 확신을 얻습니다. 격리는 핵심 제품 약속입니다.

테넌트 격리 · 신원 · 권한 부여

한 고객의 코드·발견·스캔 이력·텔레메트리·인텔리전스가 다른 고객에게 절대 보이지 않아야 한다는 원칙 위에 있습니다. 단일 통제에 의존하지 않고 평면(plane)별로 여러 계층을 겹칩니다:

이렇게 API·처리·스토리지·텔레메트리·운영 평면 전반에서 고객 데이터가 분리됩니다. 결과적으로 매우 민감한 데이터를 다루면서도 Defender와 동일한 분리·접근 규율·감사 기대치를 유지합니다.

목표는 코드를 축적하거나 취약점 아티팩트를 무기한 보존하는 것이 아니라, 분석·가치 생성·Defender 연계 후 필요한 것만 남기는 것입니다. 신뢰에는 분명한 경계가 필요합니다.

책임 있는 AI · 보안 리뷰 · 운영 거버넌스

책임 있는 AI는 끝에 덧붙이는 계층이 아니라 엔지니어링 모델의 일부입니다. 악용 가능한 취약점을 추론할 만큼 강력하기에, 바로 그 힘이 신중한 거버넌스·인간 감독·투명성·운영 통제를 요구합니다. MDASH는 다음 전반의 광범위한 리뷰(형식이 아닌 실질)를 거쳐 개발됐습니다:

보안프라이버시컴플라이언스책임 있는 AI 아키텍처권한 부여테넌트 격리침투 테스트운영 준비성
결론 목표는 "취약점을 찾는 AI"가 아니라, 규제·민감·글로벌 분산 환경에 안심하고 배포할 수 있는 신뢰 가능한 보안 서비스입니다. 강력함과 통제를 동시에 만족시키는 것이 이 아키텍처의 핵심입니다.
