Microsoft Defender · Security Exposure Management

Agentic 코드 보안 (Codename MDASH)

멀티모델 에이전트 AI 시스템으로 코드 취약점을 기존 정적 분석보다 깊고 정확하게 탐지하는 Microsoft Defender 기능입니다. 이 가이드는 공식 Microsoft Learn 문서를 한글로 정리한 비공식 학습 자료입니다.

Codename MDASH — Agentic 코드 스캐너는 Defender CLI를 확장해 전통적 정적 분석을 넘어서는 에이전트 기반 코드 스캐닝을 제공합니다. 100개 이상의 특화된 AI 에이전트가 여러 LLM에 걸쳐 협업하며 취약점을 찾고, 검증하고, 증명합니다.

주요 기능(Capabilities)

기능설명
AI 기반 취약점 탐지저장소 코드를 멀티모델 에이전트 파이프라인에 제출해 전통적 정적 분석보다 깊이 있게 취약점을 식별합니다.
세분화된 신뢰도 점수각 발견 항목을 UNLIKELY ~ PROVEN의 10단계 신뢰도 체계로 평가해 정밀한 우선순위 지정이 가능합니다.
AI 생성 코드 수정defender fix 명령으로 스캔 결과에서 직접 코드 수정본을 생성·적용합니다.
Defender 포털 중앙 집중발견 항목을 Microsoft Security Exposure Management에 게시해 조직 전체에서 추적·분류합니다.
CI/CD 통합자동화 파이프라인의 일부로 실행되며, GitHub Advanced Security·Azure DevOps 등과 호환되는 SARIF를 출력합니다.

동작 방식 — 다단계 에이전트 파이프라인

특화된 AI 에이전트들이 협업하여 취약점을 찾고, 검증하고, 증명합니다.

  • Prepare(준비) — 콜 그래프 분석과 코드 복잡도 지표로 파일 위험도를 순위화하여, 취약점 가능성이 높은 함수를 우선순위에 둡니다.
  • Scan(스캔) — 100개 이상의 특화 AI 에이전트(예: injection-auditor, memory-safety-auditor, auth-bypass-auditor)가 여러 LLM으로 순위화된 코드를 분석합니다. 각 에이전트는 특정 취약점 클래스를 담당합니다.
  • Validate(검증) — LSP 서버를 통한 taint 분석·타입 해석을 사용하고, 멀티모델 에이전트 토론(debate)으로 신뢰도를 정제하며 오탐을 제거합니다.
  • Dedup(중복 제거) — 중복 발견 항목을 통합해 고유하고 실행 가능한 최종 취약점 집합을 만듭니다.

핵심 특징(Key features)

특징설명
멀티모델 에이전트 아키텍처단일 LLM 프롬프트가 아니라, 여러 모델에 걸쳐 조율되는 100개+ 특화 에이전트.
10단계 신뢰도 체계UNLIKELY ~ PROVEN의 세분화된 신뢰도 점수로 정밀한 우선순위 지정.
통합 리메디에이션defender fix가 스캔 결과에서 AI 기반 코드 수정을 생성.
포털 통합결과가 Microsoft Security Exposure Management에 게시되어 추적·수정.

언어 지원

MDASH는 코드베이스 전반에서 범용적으로 동작하며 모든 주요 프로그래밍 언어를 지원합니다. 서로 다른 역할·전문성을 가진 100개 이상의 에이전트를 보유하며, 특히 C, C++, Java, C#에 깊은 전문성을 가진 전용 튜닝 에이전트가 학습돼 있습니다. 탐지·우선순위 품질 향상을 위해 새로운 에이전트와 전문성이 지속적으로 추가됩니다.

기본 개념

MDASH는 무엇을 하나요?
Microsoft Autonomous Code Security 팀이 만든 멀티모델 에이전트 스캐닝 시스템입니다. LLM으로 소스코드를 분석해 잠재적 악용 가능성을 평가합니다. 제로데이·로직 결함 탐지 신뢰도를 높이고, 코드 발견을 런타임 배포 맥락과 상관분석해 실제 노출 위험을 우선순위화하며, 독립 AI 모델로 교차 검증하고, 발견을 Critical·Important 등 심각도 계층으로 AI 분류합니다.
높은 수준에서 어떻게 동작하나요?
Prepare(소스 수집·언어 인식 인덱스·과거 git 커밋 분석으로 공격 표면 매핑) → Scan(특화 auditor 에이전트가 가설·근거와 함께 후보 발견 생성) → Validate(debaters가 도달성·악용성 찬반 논쟁) → Dedupe(동일 발견 통합) → Prove(트리거 입력을 구성·실행해 취약점을 동적으로 증명).
어떤 취약점을 찾도록 설계됐나요?
패턴 매칭으로 찾기 어려운 깊고 복잡한 버그(use-after-free, double-free, 버퍼 오버플로 등 여러 파일·호출·분기를 넘나드는 메모리 안전 이슈)에 초점. Windows·Hyper-V·Azure 가상화·AD DS 등 복잡한 코드에도 적용됩니다. 정적 분석·수동 검토를 대체하지 않고 깊은 추론 계층을 추가합니다.
시그니처 기반인가요? 제로데이도 찾나요?
시그니처 기반이 아닙니다. AI/LLM 추론으로 취약점 패턴을 분석합니다(과거 CVE·패치 지식은 활용). 그래서 제로데이 등 미지 취약점 식별에 도움이 될 수 있습니다.
소스코드인가요, 컴파일된 바이너리인가요?
소스코드에서 동작하며, 컴파일된 바이너리나 JAR 파일은 지원하지 않습니다.
언어·환경 지원 (OT/PLC 포함)
코드베이스 전반 범용 동작. 100개+ 에이전트를 보유하고 산업용 컨트롤러·PLC(OT)의 도메인 특화 언어 포함 전문성을 지속 확장. 현재 C, C++, Java, C#에 특히 깊은 전문 에이전트가 학습돼 있습니다.
Windows 전용인가요? Mac·Linux는?
Defender CLI는 Windows, Mac, Linux에서 사용할 수 있습니다.

모델

여러 모델을 쓰면 결과가 그때그때 최고 모델에 의존하나요?
그래서 아키텍처가 모델 비종속(model-agnostic)으로 설계됐습니다. 더 나은 모델이 나오면 파이프라인 재구축 없이 통합할 수 있고, 타게팅 로직·검증 단계·에이전트 구성·prove 인프라가 그대로 이어집니다. 가치는 특정 모델이 아니라 오케스트레이션에 있습니다.
어떤 AI 모델을 쓰나요?
고객이 Microsoft Foundry에서 접근 권한을 프로비저닝하는 다양한 모델을 사용합니다. 멀티모델 설계로 시간이 지나며 모델을 교체할 수 있고, Foundry를 통해 각 모델의 토큰 소비량을 확인할 수 있습니다.
자체 모델·에이전트(BYOA)를 쓸 수 있나요?
현재는 불가합니다. Foundry에서 지원되는 모델 중 선택할 수 있지만, 자체 모델을 가져오거나 커스텀 에이전트를 만들/가져올 수 없습니다.

리메디에이션 / 자동 수정

MDASH가 자동으로 코드를 고치나요?
아니요. MDASH는 읽기 전용입니다. 취약점을 발견하고 리메디에이션 가이드가 포함된 발견을 생성할 뿐, 환경을 수정하거나 PR을 열거나 자동 적용하지 않습니다. Defender CLI의 defender fix가 수정안을 제안하지만, 개발자가 검토·승인해야 합니다.
자동 수정(autofix) 워크플로 요건은? Foundry 흐름인가요?
Defender CLI + GitHub Copilot CLI + SARIF 출력이 있는 완료된 MDASH 스캔이 필요합니다. SARIF 발견으로 로컬 저장소에 수정안을 생성하는 개발자 주도의 별도 흐름이며 Foundry 흐름이 아닙니다. 변경은 개발자가 검토·승인해야 합니다.
GitHub를 쓰지 않으면?
로컬로 clone한 임의의 git 기반 저장소를 스캔할 수 있습니다. 다만 autofix는 로컬 코드 변경에 GitHub Copilot이 필요합니다.

CI/CD · 운영

CI/CD 파이프라인에 통합할 수 있나요?
예. 대화형 로그인으로 로컬 스캔하거나, client secret을 가진 Entra 앱 등록으로 비대화형 인증해 CI/CD에 통합합니다. 스캔이 장시간·비결정적이라 빌드 차단 게이트보다 비동기 보안 검토에 적합합니다.
설정 난이도·전문성은?
프리뷰 약관 수락 → Foundry 인퍼런스 구성 → CLI 다운로드로 스캔하거나 GitHub 저장소 연결 후 포털에서 스캔 시작. 보안 관리자·개발자·DevOps 팀에 걸친 어느 정도의 전문성이 필요합니다.
지속 사용? 주기적/배치 분석용?
고정 소요시간은 없습니다. 코드 규모(LoC)·언어·저장소 복잡도·발견 수에 따라 다르며, 장시간·비동기로 실행될 수 있습니다.
온프렘·클라우드 저장소를 지원하나요?
둘 다 지원합니다. 현재 검증 단계에서는 스캔할 저장소를 스캐너가 도는 테스트 머신에 clone해야 합니다.
저장소 읽기 전용 접근으로 충분한가요?
예, 충분합니다.
현재 규모 제한은?
저장소당 약 256 MB(변경 가능). 이 단계에서는 테넌트당 동시 스캔 1건(변경 가능, 환경별 상이 가능). 프리뷰에서는 용량이 주요 제약이며, 품질 보호를 위해 스캔이 의도적으로 rate-limit됩니다.

데이터 · 컴플라이언스

고객 데이터는 어디서 처리·저장되나요 (데이터 레지던시)?
고객 소스코드·스캔 결과는 고객의 Defender XDR 테넌트 내에 해당 테넌트와 같은 리전에서 암호화되어 저장됩니다. 처리도 같은 리전에서 이뤄지며, 소스코드 인퍼런스는 고객이 Foundry 엔드포인트 연결 시 지정한 리전에서 실행됩니다(적용 서비스 약관에 따름).
DPA 적용 여부?
프라이빗 프리뷰에서는 DPA의 Previews 섹션(삭제 포함)이 적용됩니다. 구체적 보존·삭제 일정은 별도로 다룹니다.
업로드 데이터 분류: Cache/Persistent/Backup?
Persistent.
상세/verbose 로깅은? 무엇이 캡처되나요?
MDASH는 감사 추적으로 권한 사용자 작업(CLI 온보딩, Foundry 연결/해제, 스캔 시작/취소/업로드/조회/내보내기)을 타임스탬프·사용자·클라이언트 IP·스캔 ID·코드 대상·소스 표면·결과와 함께 캡처합니다. 소스코드는 로깅되지 않습니다. 감사 이벤트는 고객 Entra 테넌트 로그에 남고 Microsoft Purview로 조회합니다. (상세는 감사 로그 이벤트.)
라이선스 전제는?
적격 Microsoft Defender XDR 플랜이 있어야 하며, MDASH를 Defender 포털에서 활성화·구성해야 합니다. 적격 라이선스로 Defender XDR에 접근 가능한 고객이 MDASH 참여 자격을 가집니다.
